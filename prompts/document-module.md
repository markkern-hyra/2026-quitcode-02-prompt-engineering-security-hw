# Документація контракту модуля

## Роль

Розробник, який пише документацію для колег: описує те, що код робить
насправді, і чесно позначає те, що не визначено.

## Мета

Додати до `app/src/quote.ts` TSDoc, з якого розробник без читання тіл функцій
знає одиниці, допустимі входи, правила округлення й відомі невизначеності.

## Контекст

- `app/src/quote.ts` — три експортовані функції й інтерфейс `QuoteInput`;
  наявні докстрінги українською.
- `app/src/quote.test.ts` — тести як джерело фактичної поведінки.
- Рішення продукту: залишок у `splitInstallments` розподіляється на перші
  платежі.
- Відкриті питання контракту (рішення ще немає, валідації в коді немає):
  `parts ≤ 0` або дробове; знижка поза 0..100; від'ємні `hours`, `rateCents`,
  `totalCents`; дробові центи на вході `formatMoney`.
- Команди: `cd app && npm test`, `cd app && npm run typecheck`.
- Як запускати приклади й перевіряти поведінку: тимчасовий файл
  `app/src/_examples.ts` з `import { … } from "./quote.ts"` і `console.log`,
  команда `cd app && node --experimental-strip-types src/_examples.ts`; після
  перевірки файл видали. Інших способів запуску TypeScript у проєкті немає
  (без `tsx`, `ts-node`, `npx`, збірки).

## Обмеження

- Змінюй лише коментарі в `app/src/quote.ts` — жодного рядка коду.
- Мова тексту — українська, як у наявних докстрінгах; теги TSDoc — стандартні
  (`@param`, `@returns`, `@example`).
- Не обіцяй поведінки, якої немає: невизначене позначай «Не визначено: …» разом
  із фактичною поточною поведінкою, а не як гарантію. Пиши це в описі функції
  **до** тегів `@param` / `@example` — текст після `@example` належить прикладу.
- Не пиши жодного твердження про поведінку (округлення, формула, «завжди»,
  «поточна реалізація»), якого не перевірив запуском.
- Якщо команду відхилено (немає дозволу), не повторюй її — скористайся способом
  із «Контексту». Та сама команда відхилена двічі — зупинись і напиши у звіті,
  чого бракує.
- Без нових файлів, окрім тимчасового `_examples.ts`, який видаляєш.

## Acceptance criteria

- [ ] Кожна експортована функція має TSDoc з `@param` (з одиницями: центи,
      години, відсотки) і `@returns`; кожне поле `QuoteInput` має коментар з
      одиницями.
- [ ] Для кожної функції описано правило округлення або розподілу залишку.
- [ ] Кожна функція має `@example`, і **кожен приклад перевірено запуском** —
      показано команду й вивід, результат збігається з написаним.
- [ ] Кожне відкрите питання з «Контексту» позначено біля відповідної функції
      як «Не визначено: …» з фактичною поточною поведінкою.
- [ ] **Кожне** твердження про поведінку в TSDoc (приклад, правило округлення,
      формула, інваріант, «поточна реалізація») має рядок у таблиці перевірки з
      фактичним виводом запуску; тверджень без запуску немає.
- [ ] `git diff app/src/quote.ts` містить лише рядки коментарів — показано
      перевірку; тимчасового `_examples.ts` у `git status` немає.
- [ ] `cd app && npm test` зелений, `cd app && npm run typecheck` без помилок.

## Формат відповіді

1. Диф `app/src/quote.ts`.
2. Таблиця перевірки: `твердження або приклад | вхід | фактичний вивід | ✅/❌`.
3. Доказ, що змінено лише коментарі.
4. «Помічено, але не чіпав» — проблеми в коді, які виявила документація.

## Stop

Після зелених тестів зупинись. Код не виправляй, навіть якщо документування
виявило проблему, — внеси її в «Помічено, але не чіпав».

## Журнал змін

- **v2** — прогін v1 провалився: агент хотів запускати приклади через
  `npx tsx`, отримав відмову в дозволі й **143 рази поспіль** повторив ту саму
  команду, вичерпав бюджет ($5) і не видав звіту. TSDoc він написав «з
  читання коду» — і 4 твердження виявились хибними (напр. «банківське
  округлення», хоча `Math.round(2.5)` = 3; `formatMoney(123.456)` → «"$1.23"»,
  хоча насправді `"$1.23.456000000000003"`). Додано: точний спосіб запуску,
  правило «двічі відхилена команда — стоп», критерій «кожне твердження
  підтверджене запуском», місце «Не визначено» до тегів.
- **v1** — перша версія.
