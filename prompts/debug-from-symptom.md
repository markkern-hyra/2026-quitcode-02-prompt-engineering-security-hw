# Дебаг: від симптому до мінімального виправлення

## Роль

Senior TypeScript-розробник на чергуванні: спершу відтворює і доводить
першопричину, потім виправляє найменшою можливою зміною.

## Мета

Знайти першопричину розбіжності між кошторисом і сумою платежів та виправити її
мінімальною зміною, підтвердженою тестами.

## Контекст

- Симптом від бухгалтерії: «Кошторис на $1.00 розбили на 3 платежі — у рахунках
  разом $0.99. В іншому проєкті $1,000.07 на 7 платежів дали на 2 центи
  більше, ніж у кошторисі».
- Код: `app/src/quote.ts` (функція `splitInstallments`). Тести:
  `app/src/quote.test.ts` — у ньому є тести `it.fails` з коментарями `// ВАДА:`,
  які вже документують цю ваду.
- Рішення продукту: залишок від ділення розподіляється по 1 центу на **перші**
  платежі — платежі відрізняються щонайбільше на 1 цент, більші йдуть першими
  (100 на 3 → `[34, 33, 33]`).
- Домен: усі суми — цілі числа в центах.
- Команди: `cd app && npm test`, `cd app && npm run typecheck`.

## Обмеження

- Спершу відтвори симптом — до будь-яких змін у коді. Відтворення — лише
  тимчасовим тестом Vitest `app/src/_repro.test.ts` (результати виводь через
  `console.log`), запуск `cd app && npm test -- src/_repro.test.ts`; наприкінці
  файл видали. `node`, `npx` і пакети поза `app/package.json` не використовуй.
- Змінюй лише тіло `splitInstallments` у `app/src/quote.ts` і тести цієї вади в
  `app/src/quote.test.ts`. Сигнатури, інші функції й інші тести не чіпай.
- Не додавай валідацію. Поведінка на входах, які контракт не визначає
  (`parts ≤ 0` або дробове, від'ємні чи дробові суми), **може** змінитися як
  побічний ефект виправлення — але тільки з таблицею «до / після» у звіті;
  рішення, чи прийнятна зміна, — за людиною. Не підганяй виправлення, щоб
  зберегти стару поведінку на цих входах.
- Якщо команду відхилено (немає дозволу), не повторюй її — зупинись і напиши, чого
  бракує.
- Не додавай залежностей.

## Acceptance criteria

- [ ] До виправлення показано відтворення обох випадків симптому: команда і
      вивід із розбіжністю сум.
- [ ] Першопричину названо одним реченням із `файл:рядок`.
- [ ] Для цілих `totalCents ≥ 0` і цілих `parts ≥ 1`: довжина результату —
      `parts`, сума частин дорівнює `totalCents`, різниця між найбільшою й
      найменшою частиною ≤ 1, частини не зростають.
- [ ] `splitInstallments(100, 3)` повертає `[34, 33, 33]`, а сума
      `splitInstallments(100007, 7)` дорівнює `100007`.
- [ ] Усі `it.fails` цієї вади перетворено на звичайні `it`, їхні коментарі
      `// ВАДА:` прибрано; у виводі `npm test` немає `expected fail`.
- [ ] Додано регресійний тест саме на два випадки із симптому.
- [ ] Диф `app/src/quote.ts` торкається лише тіла `splitInstallments`.
- [ ] Для невизначених входів (`parts` = 0, від'ємне, дробове; від'ємний або
      дробовий `totalCents`) показано таблицю «до / після виправлення», отриману
      запуском тимчасового тесту на обох версіях; кожну зміну поведінки явно
      позначено у звіті (без додавання валідації — рішення за людиною).
- [ ] Жодного виклику `node` / `npx` і жодних пакетів поза `app/package.json`;
      тимчасового `_repro.test.ts` у `git status` немає.
- [ ] `cd app && npm test` зелений, `cd app && npm run typecheck` без помилок.

## Формат відповіді

1. Відтворення: команда і вивід — до змін.
2. Першопричина: одне речення + `файл:рядок`.
3. Виправлення: диф `app/src/quote.ts`.
4. Невизначені входи: таблиця `вхід | до | після | змінилось?`.
5. Які тести змінено й додано — і чому.
6. «Помічено, але не чіпав» — список.
7. Останні 15 рядків виводу `npm test`.

## Stop

Після зелених `npm test` і `npm run typecheck` зупинись. Не виправляй інших
функцій і не додавай валідацію, навіть якщо бачиш проблеми, — лише перелічи їх
у «Помічено, але не чіпав».

## Журнал змін

- **v3** — за рев'ю CodeRabbit: (1) прибрано суперечність — v2 одночасно
  забороняв змінювати невизначену поведінку й вимагав таблицю «до / після» цих
  змін; тепер зміна дозволена лише зі звітом і рішенням людини; (2) у проєкті
  заборонено `Bash(node:*)`, тож відтворення — тимчасовим тестом Vitest через
  `npm test`; (3) Stop вимагає й `npm run typecheck`, як і критерії; (4) правило
  «відхилену команду не повторювати».
- **v2** — прогін v1 виправив ваду правильно, але непомітно змінив поведінку
  для невизначених входів: `splitInstallments(100, 2.5)` раніше кидав
  `RangeError`, після виправлення мовчки повертав `[40, 40, 40]` (сума 120).
  Заборона «не змінюй невизначену поведінку» була, а перевірки — ні. Додано
  критерій з таблицею «до / після» і розділ у форматі відповіді. Також v1 для
  відтворення виконав `npx tsx`, що завантажив пакет із npm, — додано
  заборону пакетів поза `package.json`.
- **v1** — перша версія.
