# Тести для модуля `$ARGUMENTS`

Промпт-джерело: `prompts/add-tests.md` (v2), узагальнений під будь-який модуль.

## Роль

Senior TypeScript-розробник, який пише тести, щоб знайти дефекти, а не
підтвердити поточну поведінку.

## Мета

Розширити покриття `$ARGUMENTS` тестами на крайові випадки й доменні інваріанти
так, щоб вони виявили реальні вади, — не змінюючи продакшн-код.

## Контекст

- Прочитай перед роботою: `$ARGUMENTS`; його тестовий файл поруч
  (`<ім'я>.test.ts`; якщо файлу немає — створи); `package.json` найближчого
  пакета (тест-раннер, `"type"`, скрипти).
- Доменні інваріанти визнач із коду й докстрінгів. Напр. для грошей: суми — цілі
  центи, сума частин дорівнює цілому, округлення не створює й не губить центів.
- Команди — зі `scripts` у `package.json` (напр. `npm test`, `npm run typecheck`).

## Обмеження

- Змінюй лише тестовий файл модуля. `$ARGUMENTS` не чіпай, навіть якщо знайшов
  ваду, — виправлення це окрема задача.
- Наявні тести не видаляй і не переписуй — лише додавай нові.
- Без нових залежностей; наборові перевірки — `it.each` або цикли по фіксованих
  значеннях. Детерміновано: без `Math.random` і часу.
- Не вигадуй контракт: поведінку, не визначену ні кодом, ні докстрінгом, не
  закріплюй тестом — винеси у «Відкриті питання».
- Не встановлюй і не запускай пакети поза `package.json`. Команду відхилено
  двічі — зупинись і напиши, чого бракує.

## Acceptance criteria

- [ ] Для кожної експортованої функції розглянуто 0, від'ємні значення, межі,
      округлення, великі значення — тестом або пунктом у «Відкритих питаннях».
- [ ] Для кожного доменного інваріанту є параметризований тест на ≥10
      комбінаціях, з них ≥5 — на межах чи неподільних випадках.
- [ ] Тест, що падає на поточному коді, — `it.fails(...)` з assertion на
      **правильну** поведінку і коментарем
      `// ВАДА: <функція>(<вхід>) → <факт>, очікується <очікування>`.
- [ ] Наявні тести не змінено; `git diff --stat` — зміни лише в тестовому файлі.
- [ ] Немає `.only`, `.skip`, `console.log`, `debugger`.
- [ ] Тести й typecheck зелені (включно з `it.fails`).

## Формат відповіді

1. Таблиця `функція | що перевіряє тест | ✅ проходить / 🐞 it.fails`.
2. Знайдені вади: функція, мінімальний вхід, факт, очікування.
3. Відкриті питання щодо контракту.
4. Останні 15 рядків виводу тестів.

## Stop

Після зелених тестів зупинись: не виправляй модуль, не рефактор, не додавай
інших файлів. Покажи звіт і чекай на рішення щодо вад.
