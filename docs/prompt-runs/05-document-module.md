## 05a — v1 ❌

Від коміту `9ad3fd6`, паралельно з 03 і 04.

| | |
|---|---|
| Ходів / вартість / час | **164 / $5.01 / 491 с — зупинено стелею `--max-budget-usd 5`** |
| Фінальний звіт | **немає** (`error_max_budget_usd`) |
| Відмови в дозволах | 145: 2× `cd app && npx tsx -e …`, **143× `npx tsx check-behavior.mjs` поспіль** |
| Змінені файли | `app/src/quote.ts` — лише коментарі ✅ (перевірено: жодного зміненого рядка коду) |
| `npm test` / typecheck | ✅ 41 passed / ✅ |

Що сталося: агент написав тимчасовий скрипт для перевірки поведінки, `node`
його не запустив (`ERR_MODULE_NOT_FOUND: Cannot find module './app/src/quote.js'`
— у проєкті лише TypeScript-джерело, зібраного `.js` немає), тоді агент узявся
за `npx tsx` — а `npx` після прогону 02 прибрано з allowlist. Замість змінити підхід модель 143 рази
поспіль повторила ту саму відхилену команду. Потім написала: «Спробую
використати наявні тести з файлу, а також отримати інформацію з коду
безпосередньо» — і склала TSDoc **з читання коду, без запусків**. Бюджет
закінчився до звіту.

Приклади `@example` виявились правильними (6/6), але чотири твердження про
поведінку — **хибні**. Перевірено запуском:

| Твердження в TSDoc v1 | Насправді |
|---|---|
| «Округлення: банківське (Math.round) — 0.5 округлюється до найближчого парного» | `Math.round(0.5)` = 1, `Math.round(2.5)` = **3** — не банківське |
| «Формула: `Math.round(hours * rateCents * (1 - discountPercent / 100))`» | розходиться з кодом: `hours=1, rateCents=5, discount=90` → код **1**, формула **0** |
| «`formatMoney(123.456)` → "$1.23"» | **`"$1.23.456000000000003"`** — документація приховала справжню ваду |
| «Інваріант: сума всіх платежів **завжди** дорівнює `totalCents`» | `splitInstallments(100, 2.5)` → `[40, 40]`, сума **80** |

Висновки:
1. **Критерій «перевір запуском» без робочого способу запуску не працює.**
   Промпт вимагав запуску, але не казав як, а дозволи прибрали звичний агенту
   спосіб.
2. **Stop-правило має покривати відмови в дозволах.** Без нього модель
   зациклилась; врятувала лише стеля бюджету.
3. **Документація «з читання коду» впевнено бреше** — і ховає реальні вади
   (`formatMoney` із дробовими центами).

Диф v1 на гілку **не взято**.

## 05b — v2

Від коміту `6617b3c` (після рефакторингу тестів).
Додано: точний спосіб запуску (`node --experimental-strip-types` + тимчасовий
файл), «двічі відхилена команда — стоп», критерій «кожне твердження
підтверджене запуском», місце для «Не визначено» до тегів.

| | |
|---|---|
| Ходів / вартість / час | **22 / $0.86 / 220 с** (v1: 164 / $5.01 / 491 с) |
| Відмови в дозволах | **0** (v1: 145) |
| Як перевіряв | `_examples.ts` + `node --experimental-strip-types src/_examples.ts`, файл потім видалив |
| Змінені файли | `app/src/quote.ts` — лише коментарі ✅ (перевірено незалежно) |
| `npm test` / typecheck | ✅ 34 passed / ✅ |
| Таблиця перевірки | 15 тверджень із фактичним виводом — **15/15 підтверджено** моїм окремим запуском |

Нове, чого не було у v1:
- справжня поведінка на дробових центах: `formatMoney(100.5)` → `"$1.0.5"`
  (задокументовано як «Не визначено» й винесено в «Помічено, але не чіпав»);
- знахідка: для від'ємного `totalCents` залишок потрапляє на **останні**
  платежі (`(-100, 3)` → `[-33, -33, -34]`), на відміну від додатних сум.

**Що довелось поправити руками.** Одне твердження не потрапило в таблицю
перевірки і виявилось хибним — те саме, що й у v1:
«Формула: `Math.round(hours * rateCents * (1 - discountPercent / 100))`».
Код рахує інакше, і результати розходяться (`hours=1, rateCents=5,
discountPercent=90` → код `1`, формула `0`). Рядок замінено на опис того, що
справді написано в коді: `gross = hours * rateCents`, знижка
`gross * discountPercent / 100`, результат `Math.round(gross - знижка)`.
Критерій «кожне твердження — з рядком у таблиці» агент порушив саме на
твердженні, яке здавалось йому очевидним.

## Рішення

Диф v2 узято на гілку з однією ручною правкою змісту (рядок формули). Пізніше,
після незалежного рев'ю, — ще одна правка правопису в тому самому TSDoc:
«половина центу» → «половина цента».

## Висновки

- Промпт-артефакт — це не лише текст, а й **середовище**, в якому він
  виконується: v1 і v2 відрізняються здебільшого тим, що v2 каже, *як*
  перевіряти, і що робити при відмові в дозволі.
- Критерій «перевір запуском» зменшив кількість хибних тверджень з 4 до 1, але
  не до нуля: модель пропускає перевірку того, в чому впевнена. Фінальне
  рев'ю людиною лишається обов'язковим.

## 05c — v3 (після рев'ю CodeRabbit)

Що змінено: інвентар усіх тверджень з ID і механічна звірка «інвентар = тести
= рядки таблиці»; перевірка — тимчасовим тестом `_claims.test.ts` (у проєкті
заборонено `Bash(node:*)`); Stop — з `typecheck`. Від того самого `6617b3c`, що
v2. Сирий вихід — [`e2-document-module-v3`](./raw/e2-document-module-v3.md).

| | |
|---|---|
| Ходів / вартість / час | 41 / $1.58 / 312 с |
| Запуски | `npm test -- src/_claims.test.ts`; **0 спроб `node`**; тимчасовий файл видалено |
| Звірка | **інвентар = 20, тестів = 20, рядків таблиці = 20** ✅ — жодного твердження поза таблицею |
| Лише коментарі / `npm test` / typecheck (незалежно) | ✅ / ✅ 34 passed / ✅ |
| Відмови й блукання | 3 відмови (2× `cd …`, 1× `git -C …`); ~18 спроб отримати `git diff`, бо агент запускав його з `app/` із шляхом від кореня |

**Хибна формула повернулась — і «пройшла» перевірку.** Твердження C1:
«Формула: `Math.round(hours * rateCents * (1 - discountPercent / 100))`» —
те саме, що у v1 і v2. Цього разу воно було в інвентарі й у таблиці, але тест
узяв вхід `(7, 3333, 17 %)`, на якому код і формула збігаються (19365). На
`(1, 5, 90 %)` код дає **1**, формула — **0** (перевірено одноразовим тестом
Vitest). Механічна звірка закрила прогалину «твердження поза таблицею», але
відкрила наступну: **один приклад не перевіряє загальне твердження**, якщо
хибне формулювання на цьому прикладі дає той самий результат.

Промпт → v4: загальні твердження — сіткою ≥1000 комбінацій із дробовими
відсотками; формулу записувати лише так, як її рахує код. На гілку результат
не брався (у ньому хибна формула).

## 05d — v4 (друга ітерація після рев'ю CodeRabbit)

Що змінено: загальні твердження (формула, округлення, інваріанти) — перевірка
**сіткою** ≥1000 комбінацій із дробовими відсотками; формулу записувати лише
так, як її рахує код. Від того самого `6617b3c`, з `Bash(node:*)` у `deny`.
Сирий вихід — [`f1-document-module-v4`](./raw/f1-document-module-v4.md).

| Лише коментарі / `npm test` / typecheck (незалежно) | ✅ / ✅ 34 passed / ✅ |

**Незалежна перевірка формули:** одноразовий тест Vitest порівняв задокументований
вираз із `estimateTotalCents` на **114 440** комбінаціях (години 0–60, ставки
1–400, знижки 0 / 1 / 7 / 12.5 / 17 / 33 / 33.33 / 50 / 66.6 / 90 / 99.9 / 100 /
150 / −10 %, плюс `(1, 5, 90 %)`, на якому впала формула v1–v3) — **0
розбіжностей**.

Висновок: прогалину v3 закрито. Три ітерації дали три різні механізми проти
однієї хибної формули: «перевір запуском» (v2) → «кожне твердження в таблиці»
(v3) → «загальне твердження — сіткою, формула — як у коді» (v4). На гілку TSDoc
v4 не брався: чинний TSDoc (v2 + ручна правка формули) уже коректний.
