# Журнал прогонів промптів

Тут — сліди того, що кожен промпт із `prompts/` справді запускали: що агент
прочитав і змінив, чим закінчились тести, скільки коштувало і що довелось
поправити. Промпт без запису тут — чернетка, а не артефакт.

## Методика

Кожен прогін — **свіжа headless-сесія** Claude Code, яка не бачить цієї розмови:

- окремий `git worktree` від поточного коміту гілки + `npm ci` — прогін не
  чіпає робочу копію, а результат можна порівняти чи відкинути;
- `claude -p "<текст промпту>" --output-format stream-json --verbose` — повний
  лог кожного виклику інструмента;
- `--strict-mcp-config` — MCP-конектори (n8n, Figma) вимкнені: прогін не має
  доступу ні до чого поза worktree;
- `--permission-mode acceptEdits` + allowlist Bash. Прогони 00–02: `npm`,
  `npx`, `node`, `git diff|status|log`. Після того як у прогоні 02a агент через
  `npx` завантажив пакет із мережі, для наступних прогонів allowlist звужено до
  `npm test`, `npm run typecheck`, `node`, `git diff|status|log|checkout`.
  Прогони після рев'ю CodeRabbit (`e*`, `f*`, `g*`) — з налаштуваннями, де
  `Bash(node:*)` у `deny` (в allowlist `node` лишено навмисно: перевірка, що
  `deny` перемагає), і без `git checkout`;
- `--max-budget-usd 5` — стеля вартості на прогін;
- `docs/prompt-runs/` прибирається з worktree (`skip-worktree` + видалення) —
  агент не бачить висновків попередніх прогонів і не може їх переказати;
- після прогону — незалежно від агента: скрипт фіксує `git diff` і `npm test`, а
  з другого раунду рев'ю CodeRabbit (прогони `g*`) — ще й `npm run typecheck`.
  До того typecheck для кожного прогону, що змінював код, запускався окремою
  командою під час аналізу (для 05a — повторно, з дифу прогону).

Інструмент: Claude Code CLI 2.1.20, модель за замовчуванням
`claude-opus-4-5-20251101`. Скрипт — [`run-prompt.sh`](./run-prompt.sh).

Текст промпту для прогону береться з файлу в `prompts/` без frontmatter і без
службових розділів (XML-діалект — окремим прогоном).

**Сирі виходи** кожного прогону — у [`raw/`](./raw/): точний запит, послідовність
викликів інструментів (підряд однакові згорнуто, напр. `143× Bash: npx tsx …`) і
фінальна відповідь агента (у сесіях із кількома ходами людини — із заголовками
«Хід 1», «Хід 2»). Файли сформовано з stream-json логів **з редагуванням**:
фейковий ключ → `<FAKE_KEY>`, локальні шляхи, команди довші за 300 символів —
з позначкою `…[обрізано]`, багаторядкові — `…[+N рядк.]` (відсутність позначки
означає, що команду показано повністю). Поза цими замінами текст запиту й
відповіді агента не змінювався.

Повні stream-json логи **не зберігаються**: вони лежали в тимчасовому каталозі
робочої сесії (`RUNS_DIR` скрипта), тож файли `raw/` — єдиний збережений слід
прогонів. Виходи, які пізніше визнано застарілими, позначено в заголовку файлу
(напр. `e4`), а прогони на старій версії команди — окремою приміткою (напр.
`d2`); самі відповіді не переписуються. Файли `a*` — Task A, `c*` — Task C,
`d*` — Task D, `e*`, `f*`, `g*` — перевірка виправлень після рев'ю CodeRabbit.
