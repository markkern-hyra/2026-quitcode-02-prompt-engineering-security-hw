# Дебаг: від симптому до мінімального виправлення

## Роль

Senior TypeScript-розробник на чергуванні: спершу відтворює і доводить
першопричину, потім виправляє найменшою можливою зміною.

## Мета

Знайти першопричину розбіжності між кошторисом і сумою платежів та виправити її
мінімальною зміною, підтвердженою тестами.

## Контекст

- Симптом від бухгалтерії: «Кошторис на $1.00 розбили на 3 платежі — у рахунках
  разом $0.99. В іншому проєкті $1,000.07 на 7 платежів дали на 2 центи
  більше, ніж у кошторисі».
- Код: `app/src/quote.ts` (функція `splitInstallments`). Тести:
  `app/src/quote.test.ts` — у ньому є тести `it.fails` з коментарями `// ВАДА:`,
  які вже документують цю ваду.
- Рішення продукту: залишок від ділення розподіляється по 1 центу на **перші**
  платежі — платежі відрізняються щонайбільше на 1 цент, більші йдуть першими
  (100 на 3 → `[34, 33, 33]`).
- Домен: усі суми — цілі числа в центах.
- Команди: `cd app && npm test`, `cd app && npm run typecheck`.

## Обмеження

- Спершу відтвори симптом — до будь-яких змін у коді. Для відтворення —
  тимчасовий тест Vitest або `node --experimental-strip-types`; не встановлюй і
  не запускай пакети, яких немає в `app/package.json` (жодного `npx <пакет>`,
  що завантажується з мережі).
- Змінюй лише тіло `splitInstallments` у `app/src/quote.ts` і тести цієї вади в
  `app/src/quote.test.ts`. Сигнатури, інші функції й інші тести не чіпай.
- Не додавай валідацію й не змінюй поведінку, яку контракт не визначає
  (`parts ≤ 0`, від'ємні чи дробові суми), — це відкриті питання, а не цей баг.
- Не додавай залежностей.

## Acceptance criteria

- [ ] До виправлення показано відтворення обох випадків симптому: команда і
      вивід із розбіжністю сум.
- [ ] Першопричину названо одним реченням із `файл:рядок`.
- [ ] Для цілих `totalCents ≥ 0` і цілих `parts ≥ 1`: довжина результату —
      `parts`, сума частин дорівнює `totalCents`, різниця між найбільшою й
      найменшою частиною ≤ 1, частини не зростають.
- [ ] `splitInstallments(100, 3)` повертає `[34, 33, 33]`, а сума
      `splitInstallments(100007, 7)` дорівнює `100007`.
- [ ] Усі `it.fails` цієї вади перетворено на звичайні `it`, їхні коментарі
      `// ВАДА:` прибрано; у виводі `npm test` немає `expected fail`.
- [ ] Додано регресійний тест саме на два випадки із симптому.
- [ ] Диф `app/src/quote.ts` торкається лише тіла `splitInstallments`.
- [ ] Для невизначених входів (`parts` = 0, від'ємне, дробове; від'ємний або
      дробовий `totalCents`) показано таблицю «до / після виправлення», отриману
      запуском обох версій; кожну зміну поведінки явно позначено у звіті (без
      додавання валідації — рішення за людиною).
- [ ] Жодних пакетів поза `app/package.json` не встановлено й не запущено.
- [ ] `cd app && npm test` зелений, `cd app && npm run typecheck` без помилок.

## Формат відповіді

1. Відтворення: команда і вивід — до змін.
2. Першопричина: одне речення + `файл:рядок`.
3. Виправлення: диф `app/src/quote.ts`.
4. Невизначені входи: таблиця `вхід | до | після | змінилось?`.
5. Які тести змінено й додано — і чому.
6. «Помічено, але не чіпав» — список.
7. Останні 15 рядків виводу `npm test`.

## Stop

Після зеленого `npm test` зупинись. Не виправляй інших функцій і не додавай
валідацію, навіть якщо бачиш проблеми, — лише перелічи їх у «Помічено, але не
чіпав».

---

## 2. Першопричина

`Math.round(totalCents / parts)` у `app/src/quote.ts:32` округлює частку замість використання `Math.floor` і розподілу залишку, що губить або додає центи при неподільних сумах.

---

## 3. Виправлення (диф `app/src/quote.ts`)

```diff
 export function splitInstallments(totalCents: number, parts: number): number[] {
-  const each = Math.round(totalCents / parts);
-  return new Array(parts).fill(each);
+  const base = Math.floor(totalCents / parts);
+  const remainder = totalCents - base * parts;
+  return Array.from({ length: parts }, (_, i) => base + (i < remainder ? 1 : 0));
 }
```

---

## 4. Невизначені входи

| Вхід | До | Після | Змінилось? |
|------|----|-------|------------|
| `parts = 0` | `[]` | `[]` | Ні |
| `parts = -3` (від'ємне) | `Error: Invalid array length` | `[]` | **Так** — замість Error повертає `[]` |
| `parts = 2.5` (дробове) | `Error: Invalid array length` | `[40, 40]` | **Так** — замість Error повертає масив (length=2) |
| `totalCents = -100` (від'ємний) | `[-33, -33, -33]` | `[-33, -33, -34]` | **Так** — інший розподіл |
| `totalCents = 100.5` (дробовий) | `[34, 34, 34]` | `[34, 34, 33]` | **Так** — інший розподіл |

> Зміни в невизначеній поведінці не є частиною контракту — рішення за людиною.

## 5. Які тести змінено й додано

**Змінено (перетворено `it.fails` → `it`, прибрано `// ВАДА:`):**
- `зберігає суму при неподільному залишку (100, 3)`
- `зберігає суму при неподільному залишку (10, 3)`
- `зберігає суму при totalCents < parts (1, 3)`
- Цикл у блоці «інваріант» — прибрано зайвий `if/else`, тепер усі неподільні випадки теж просто `it`

**Додано (регресійний тест):**
- `describe("splitInstallments — регресія симптому бухгалтерії")` з двома тестами:
  - `$1.00 на 3 платежі: [34, 33, 33], сума = 100`
  - `$1000.07 на 7 платежів: сума = 100007`
