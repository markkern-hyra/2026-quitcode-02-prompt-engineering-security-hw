## Роль

Senior TypeScript-розробник, який пише тести для фінансової логіки й шукає

## Мета

Розширити покриття `app/src/quote.ts` тестами на крайові випадки й грошові
інваріанти так, щоб вони виявили реальні вади, — не змінюючи продакшн-код.

## Контекст

- Прочитай перед роботою: `app/src/quote.ts` (три експортовані функції),
  `app/src/quote.test.ts` (наявні happy-path тести), `app/package.json`
  (Vitest, `"type": "module"`).
- Домен: кошторис проєкту; усі суми — цілі числа в центах (див. докстрінг
  модуля). Округлення не повинно створювати чи губити центи.
- Імпорт у тестах — `./quote.js` (NodeNext), як у наявному файлі.
- Команди: `cd app && npm test`, `cd app && npm run typecheck`.

## Обмеження

- Змінюй лише `app/src/quote.test.ts`. `app/src/quote.ts` не чіпай, навіть
  якщо знайшов ваду, — виправлення це окрема задача.
- Не додавай залежностей (без fast-check тощо): наборові перевірки — звичайними
  циклами по фіксованих значеннях.
- Тести детерміновані: без `Math.random` і без залежності від часу.
- Не вигадуй контракт: якщо поведінку для входу не визначено ні кодом, ні
  докстрінгом (напр. `parts = 0`, знижка понад 100 %), не закріплюй поточну
  поведінку як правильну — винеси це у «Відкриті питання».
- Назви тестів — українською, у стилі наявних.

## Acceptance criteria

- [ ] Для кожної з трьох функцій є тести на крайові випадки: 0, від'ємні
      значення, неподільний залишок, округлення половини цента, великі суми.
- [ ] Для функцій, що перераховують або ділять гроші, є тест-інваріант «центи
      не з'являються і не зникають» (сума частин дорівнює цілому) на наборі
      щонайменше з 5 комбінацій.
- [ ] Кожен тест, що падає на поточному коді, оформлено як `it.fails(...)` з
      коментарем `// ВАДА: <вхід> → <факт>, очікується <очікування>` і
      наведено у звіті.
- [ ] `git diff --stat` показує зміни лише в `app/src/quote.test.ts`.
- [ ] `cd app && npm test` зелений, `cd app && npm run typecheck` без помилок.
- [ ] Жоден тест не закріплює як «правильну» поведінку, яку код і докстрінги
      не визначають.

4. Останні рядки виводу `npm test`.

## Аналіз промпту та код-таргету

### Контекст коду

**Три функції в `quote.ts`:**
1. `estimateTotalCents` — множить години на ставку, віднімає знижку, округлює
2. `splitInstallments` — ділить суму на рівні платежі (⚠️ очевидна вада: `Math.round` на кожен платіж, залишок губиться)
3. `formatMoney` — форматує центи у `$X,XXX.XX`

**Очевидні вади в коді:**
- `splitInstallments`: сума частин ≠ totalCents при неподільному залишку (напр., 100 центів на 3 частини → [33, 33, 33] = 99 центів)
- `splitInstallments`: parts=0 → `Infinity` або `NaN`, потім `Array(NaN).fill(...)` → `[]`

## Які acceptance criteria я додав і чому

| Додано / змінено | Обґрунтування |
|------------------|---------------|
| **Конкретні вхідні значення для кожної функції** | Оригінал казав «0, від'ємні, великі» абстрактно. Тепер явно: `hours=0`, `parts=1`, `cents=-99` тощо — LLM не вигадуватиме свої випадки, а перевірить саме ці. |
| **Мінімум 10 комбінацій для інваріанту splitInstallments** | Оригінал казав «≥5», але головна вада (втрата центів) проявляється в багатьох неподільних випадках — 10 дає кращу впевненість. |
| **Інваріант «результат — ціле число» для estimateTotalCents** | Округлення `Math.round` може маскувати проблему, але перевірка `Number.isInteger` явно фіксує очікування домену. |
| **Формат коментаря ВАДА** | Структурований формат `// ВАДА: fn(input) → actual, очікується expected` — легше парсити і перетворювати на GitHub issues. |
| **Заборона .only, .skip, console.log** | Частий антипатерн — LLM залишає дебаг-артефакти. Явна заборона попереджає це. |
| **«Видалених наявних тестів — 0»** | Захист від регресії: LLM іноді «оптимізує» наявні тести. |
| **15 рядків виводу npm test** | Оригінал не вказував скільки — може вивалити весь лог або обрізати важливе. |
| **Список конкретних невизначених випадків** | Замість абстрактного «якщо не визначено» — явний перелік: `parts=0`, `discountPercent > 100`, `discountPercent < 0`, від'ємні `hours`/`rateCents`. Це допомагає LLM структурувати «Відкриті питання». |
| **Явна вимога не змінювати наявні тести** | Оригінал казав «змінюй лише файл», але не забороняв редагувати існуючі тести — тепер явно. |
