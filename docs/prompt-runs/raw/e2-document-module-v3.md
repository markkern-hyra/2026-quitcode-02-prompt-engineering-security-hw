## 6. Помічено, але не чіпав

1. **`formatMoney` зламана для дробових центів** — `formatMoney(123.7)` повертає `"$1.23.700000000000003"`. Причина: `abs % 100` для дробового числа дає дробовий залишок із плаваючою точкою, а `padStart(2, "0")` не округлює. Потрібно або валідувати вхід, або округлювати на початку функції.

2. **`splitInstallments` поводиться несиметрично для від'ємних значень** — для позитивних `totalCents` залишок іде на перші платежі (`[4, 3, 3]`), для від'ємних — на останні (`[-33, -33, -34]`). Це може бути несподіваним для користувачів.

3. **`splitInstallments(totalCents, 0)`** повертає порожній масив, але сума елементів `[]` = 0 ≠ `totalCents`, що порушує інваріант.

4. **Відсутня валідація входів** — всі три функції приймають будь-які числа без перевірки діапазону. Для production-коду варто додати валідацію або документувати очікувані діапазони як preconditions.
