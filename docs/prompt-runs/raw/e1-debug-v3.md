## Контекст

- Симптом від бухгалтерії: «Кошторис на $1.00 розбили на 3 платежі — у рахунках

### 2. Першопричина

Використання `Math.round(totalCents / parts)` замість `Math.floor` з розподілом залишку — округлення може як зменшити, так і збільшити результат, втрачаючи інваріант `sum === totalCents` (`app/src/quote.ts:32`).

### 3. Виправлення: диф `app/src/quote.ts`

```diff
 export function splitInstallments(totalCents: number, parts: number): number[] {
-  const each = Math.round(totalCents / parts);
-  return new Array(parts).fill(each);
+  const base = Math.floor(totalCents / parts);
+  const remainder = totalCents - base * parts;
+  return Array.from({ length: parts }, (_, i) => base + (i < remainder ? 1 : 0));
 }
```

### 4. Невизначені входи: таблиця «до / після»

| Вхід | До | Після | Змінилось? |
|---|---|---|---|
| `(100, 0)` parts=0 | `[]`, sum=0 | `[]`, sum=0 | Ні |
| `(100, -3)` parts<0 | RangeError | `[]`, sum=0 | **Так** |
| `(100, 2.5)` parts дробове | RangeError | `[40, 40]`, sum=80 | **Так** |
| `(-100, 3)` totalCents<0 | `[-33, -33, -33]`, sum=-99 | `[-33, -33, -34]`, sum=-100 | **Так** (сума тепер точна) |
| `(50.5, 3)` totalCents дробове | `[17, 17, 17]`, sum=51 | `[17, 17, 17]`, sum=51 | Ні |

### 5. Які тести змінено й додано — і чому

**Змінено:**
- 3 тести `it.fails` в describe `"splitInstallments — крайові випадки"` перетворено на `it` (рядки 99–121): раніше документували ваду, тепер — регресійні тести.
- 6 тестів `it.fails` у describe `"splitInstallments — інваріант..."` для неподільних випадків об'єднано в один цикл `it` (рядки 141–148): вада виправлена.

**Додано:**
- describe `"splitInstallments — регресія симптомів бухгалтерії"` з 4 тестами:
  - точний результат `[34, 33, 33]` для `(100, 3)`;
  - сума `100007` для `(100007, 7)`;
  - частини не зростають;
  - різниця max−min ≤ 1.

### 6. «Помічено, але не чіпав»

- `estimateTotalCents` виконує `Math.round(gross - discount)`, що може округляти у різні боки — потенційно несумісно з банківськими правилами. Не чіпав.
- Поведінка `splitInstallments` на `parts=0` повертає порожній масив — можливо варто валідувати. Не чіпав за вимогою.
- Для від'ємних `totalCents` тепер сума точна, але семантика «більші спочатку» інвертується (більш від'ємні йдуть останніми). Не додавав валідацію.
