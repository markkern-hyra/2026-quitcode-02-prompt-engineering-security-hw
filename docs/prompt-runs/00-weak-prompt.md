## 00a — лише слабкий промпт

| | |
|---|---|
| Модель | `claude-opus-4-5-20251101` (Claude Code CLI 2.1.20, `claude -p`) |
| Ходів / вартість / час | 6 / $0.24 / 17 с |
| Що прочитав | `Glob **/*.{py,js,ts,tsx,jsx}` → `AGENTS.md`, `app/src/quote.ts`, `app/src/quote.test.ts`, `app/package.json` |
| Змінені файли | жодного |
| `npm test` | 4/4 (без змін) |

Фрагмент відповіді:

```
Я бачу дефект у `splitInstallments` — якщо сума не ділиться націло, всі
частини будуть однаковими й загальна сума не зберігатиметься.

Як саме ти хочеш, щоб я допоміг?
1. Розширити покриття тестами …  2. Запустити існуючі тести …
3. Знайти дефекти …               4. Щось інше — опиши детальніше
```

Без scope агент не вгадав задачу — він повернув її людині.

## 00b — той самий промпт + типова відповідь людини «розшир покриття тестами»

Другий хід у тій самій сесії (`claude -p --resume`), щоб побачити, як агент сам
визначає scope і «готово». У сирому виході
[`raw/a0b-weak-followup.md`](./raw/a0b-weak-followup.md) відповіді розділено
заголовками: **«Хід 1»** — відповідь на «допоможи з тестами для app», **«Хід 2»**
— на «розшир покриття тестами».

| | |
|---|---|
| Ходів / вартість | 4 + 6 / $0.40 + $0.18 |
| Хід 1 | запустив субагента «Explore app and test structure» (13 викликів: `find`, `ls`, `Read` README/CLAUDE/AGENTS/tsconfig…); повернув пропозицію тестів англійською і спитав «Would you like me to add these tests to the test file?» |
| Хід 2 | 3× `Edit` у `app/src/quote.test.ts` (+63 рядки, 14 нових `it`), `npm test` |
| `npm test` | **❌ 3 failed / 15 passed, exit 1** |
| `quote.ts` | не змінено (заборони не було — просто не став) |

Промпт, який агент сам написав субагенту (вгадування стека):

```
1. What is the main application (look for app.py, main.py, or similar)
2. What testing framework is used (pytest, unittest, etc.)
```

Фінальна відповідь при червоних тестах:

```
Розширення тестів завершено. Тести виявили **баг у `splitInstallments`**:
- **15 тестів пройшли** ✓
- **3 тести впали** ✗ — вони виявляють дефект
```

## Висновки

| Чого бракує в промпті | Що сталося насправді |
|---|---|
| Scope | вгадував стек (шукав Python і pytest), розвідка по всьому репо |
| Мета | «0 / від'ємні / великі» точково, жодного інваріанту на наборі значень, жодних відкритих питань щодо контракту |
| Acceptance criteria | оголосив «завершено» з червоним `npm test` |
| Обмеження | `quote.ts` не зачепив випадково, а не за правилом |
| Stop | зупинився, але в червоному стані — з таким результатом не можна мержити |

**Чесне застереження.** Walkthrough обіцяє, що слабкий промпт ваду не знайде.
На цій моделі він її **знайшов** уже в 00a: у репо є прямі підказки (докстрінг
`quote.ts` «НАВМИСНЕ недосконалий», коментар «навмисно неповні» в тестах,
`AGENTS.md`: «contains at least one real defect»). Отже, різниця між слабким і
структурованим промптом тут не в тому, *чи* знайдено ваду, а в тому, *у якому
стані* агент лишає код: червоний суїт проти зеленого з задокументованою вадою —
див. [01-add-tests.md](./01-add-tests.md).
